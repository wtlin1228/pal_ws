# pal_ws — ROS 2 palletizing / depalletizing tutorial workspace (C++ edition)

Companion repository for the 12-week tutorial "ROS 2 Palletizing & Depalletizing".
Every chapter is a tag; `master` is the final state (Ch 18).

**The tutorial itself is in this repo as a static site:** open `docs/site/index.html` in a browser
(no server, no build). The sources are the Markdown files in `docs/`; after editing them run
`python3 docs/build.py` (needs `pip install markdown`) to regenerate `docs/site/`. The drawings are
generated by `docs/img/make_svgs.py`.

```bash
git clone pal_ws.bundle ~/pal_ws        # from the bundle, or clone the repo
cd ~/pal_ws
git tag                                 # ch00 ... ch18
git checkout ch05                       # the workspace as it should look after chapter 5
git switch -c mine ch05                 # or branch from it to keep your own edits
git checkout master                     # everything
```

Each tag contains exactly what the chapter builds, including the checkpoint exercises. Build with:

```bash
rosdep install --from-paths src --ignore-src -r -y
colcon build --symlink-install && source install/setup.bash
colcon test --packages-select cell_planning cell_perception && colcon test-result --verbose
```

Language rule: every node and library the robot software is made of is C++ (`rclcpp`, Eigen, OpenCV,
MoveIt's `MoveGroupInterface`); Python remains only for the mock devices of the digital twin (`cell_sim`),
launch files and launch tests, which is also where production cells keep it.

| Package | Chapter | Holds |
| --- | --- | --- |
| `ros2_basics` | 1, 4, 5 | throwaway C++ nodes used to learn each ROS 2 mechanism |
| `cell_interfaces` | 2 | Box, BoxArray, SpawnBox, GetBoxes, SetSuction, PickPlace, RunJob |
| `cell_bringup` | 2, 13 | launch files that start several nodes |
| `cell_description` | 3, 5 | URDF/Xacro of the cell, ros2_control tag, RViz configs |
| `cell_planning` | 4, 11–15 | header-only C++: geometry, grasps, patterns, SKUs, placement plans; GoogleTest |
| `cell_moveit_config` | 6 | MoveIt configuration (hand-written reference; the Setup Assistant output is equivalent) |
| `cell_motion` | 7, 8, 11 | `Robot` over MoveGroupInterface, demos, the PickPlace action server |
| `cell_sim` | 8, 9, 14 | the Python digital twin: world_model, mock_gripper, mock_camera, mock_conveyor |
| `cell_perception` | 10 | height-map box detector (OpenCV) and its GoogleTest |
| `cell_executive` | 13–17 | the job state machine (RunJob action) and the BehaviorTree.CPP sketch |

The pure C++ libraries (`cell_planning`, `cell_perception`) and their tests were compiled and run against
Eigen, OpenCV and GoogleTest before publication; the ROS nodes are written against the Jazzy APIs from the
documentation and could not be compiled here, so expect the odd include path or signature to need a touch-up.

## Capstone (Ch 18)

```bash
ros2 launch cell_bringup cell.launch.py 2>&1 | tee run.log
ros2 param set /mock_conveyor feed_sequence ABCABCABCA
ros2 action send_goal /run_job cell_interfaces/action/RunJob "{mode: palletize, strategy: mixed}" --feedback
ros2 param set /mock_gripper fail_every_n 7; ros2 param set /mock_gripper drop_after_s 3.0
ros2 action send_goal /run_job cell_interfaces/action/RunJob "{mode: depalletize, strategy: mixed}" --feedback
python3 tools/job_stats.py run.log           # per-stage times, boxes per minute, recoveries
```

`master` differs from `ch16` in one optimization only: the executive triggers the next capture while the
robot carries a box away (`onStage`), so `DETECT` usually finds a frame waiting.
