# Ch 17 (optional) — Gazebo physics and behavior trees (week 12)

Goal: two directions you can take the cell, each worth a few days. Gazebo replaces the mock physics with real contact dynamics; a behavior tree replaces the hand-written state machine with a structure that scales to dozens of failure cases. Pick one, or skip both and go to Ch 18.

## A. Gazebo Harmonic: what changes and what does not

Jazzy pairs with Gazebo Harmonic (`ros-jazzy-ros-gz`); Lyrical pairs with Gazebo Jetty. In a VM, expect 5–15 Hz with software rendering; run the GUI only when you need it (`gz sim -s` for server-only).

| Piece | Today (kinematic twin) | With Gazebo |
| --- | --- | --- |
| Joints | `mock_components/GenericSystem` | `gz_ros2_control/GazeboSimSystem` plugin in the `<ros2_control>` tag; controllers YAML unchanged |
| World truth | `world_model` | the Gazebo world; `world_model` is deleted |
| Boxes | markers | SDF models with mass and friction, spawned with `ros_gz_sim create` |
| Camera | `mock_camera` | a `depth_camera` sensor on the camera link; `ros_gz_bridge` publishes `PointCloud2` |
| Suction | `mock_gripper` | the `DetachableJoint` system: a fixed joint created between the pad and the nearest box on "attach", removed on "detach" |
| Conveyor | `mock_conveyor` | a kinematic belt model, or boxes moved by a small plugin |
| Everything else | unchanged | unchanged: detector, grasps, server, executive, patterns |

What you learn that the mock cannot teach: a box placed with 60 % support really tips; a 0.4 m box swings on a suction pad under fast acceleration; a conveyor box that is not centered arrives at an angle. What costs you time: the suction model, friction tuning, and the VM frame rate. Keep the kinematic twin as the default and use Gazebo for specific experiments.

## B. Behavior trees with BehaviorTree.CPP

The Ch 13 loop as a tree: a `Sequence` of leaves, a `RetryUntilSuccessful` decorator around the pick, a `Fallback` for recovery. The tree is XML; each leaf is a small C++ node class that wraps one of the calls the executive already makes.

```bash
sudo apt install -y ros-jazzy-behaviortree-cpp
```

```cpp
// cell_executive/src/bt_executive.cpp (sketch of the structure; make the Executive's helpers public to use them)
#include <chrono>
#include <future>
#include <thread>
#include <behaviortree_cpp/bt_factory.h>
#include <behaviortree_cpp/action_node.h>
#include <behaviortree_cpp/condition_node.h>
#include "executive.hpp"               // the Executive class of Ch 13, moved to a header

using namespace BT;

class Capture : public SyncActionNode {
public:
  Capture(const std::string & name, const NodeConfig & cfg, Executive & ex) : SyncActionNode(name, cfg), ex_(ex) {}
  static PortsList providedPorts() { return {}; }
  NodeStatus tick() override { ex_.clearFrame(); return ex_.capture() ? NodeStatus::SUCCESS : NodeStatus::FAILURE; }
private:
  Executive & ex_;
};

class Detect : public StatefulActionNode {              // RUNNING until a frame arrives, FAILURE after 2 s
public:
  Detect(const std::string & name, const NodeConfig & cfg, Executive & ex) : StatefulActionNode(name, cfg), ex_(ex) {}
  static PortsList providedPorts() { return {}; }
  NodeStatus onStart() override { t0_ = std::chrono::steady_clock::now(); return NodeStatus::RUNNING; }
  NodeStatus onRunning() override {
    if (const auto f = ex_.waitFrame(std::chrono::milliseconds(0))) { ex_.dets = *f; return NodeStatus::SUCCESS; }
    return std::chrono::steady_clock::now() - t0_ < std::chrono::seconds(2) ? NodeStatus::RUNNING : NodeStatus::FAILURE;
  }
  void onHalted() override {}
private:
  Executive & ex_;
  std::chrono::steady_clock::time_point t0_;
};

class PalletEmpty : public ConditionNode {
public:
  PalletEmpty(const std::string & name, const NodeConfig & cfg, Executive & ex) : ConditionNode(name, cfg), ex_(ex) {}
  static PortsList providedPorts() { return {}; }
  NodeStatus tick() override { return ex_.dets.detections.empty() ? NodeStatus::SUCCESS : NodeStatus::FAILURE; }
private:
  Executive & ex_;
};

class PickPlaceLeaf : public StatefulActionNode {       // sends the goal on start, polls the result while running
public:
  PickPlaceLeaf(const std::string & name, const NodeConfig & cfg, Executive & ex) : StatefulActionNode(name, cfg), ex_(ex) {}
  static PortsList providedPorts() { return {}; }
  NodeStatus onStart() override {
    const auto goal = ex_.planPick(ex_.dets);
    if (!goal) return NodeStatus::FAILURE;
    result_ = std::async(std::launch::async, [this, g = *goal]() { return ex_.runPick(g).first; });
    return NodeStatus::RUNNING;
  }
  NodeStatus onRunning() override {
    if (result_.wait_for(std::chrono::milliseconds(0)) != std::future_status::ready) return NodeStatus::RUNNING;
    return result_.get() ? NodeStatus::SUCCESS : NodeStatus::FAILURE;
  }
  void onHalted() override {}
private:
  Executive & ex_;
  std::future<bool> result_;
};

static const char * TREE = R"(
<root BTCPP_format="4">
  <BehaviorTree ID="OneBox">
    <Sequence>
      <Capture/>
      <Detect/>
      <Fallback>
        <PalletEmpty/>
        <RetryUntilSuccessful num_attempts="3">
          <PickPlace/>
        </RetryUntilSuccessful>
      </Fallback>
    </Sequence>
  </BehaviorTree>
</root>)";

int main(int argc, char ** argv) {
  rclcpp::init(argc, argv);
  auto ex = std::make_shared<Executive>();
  rclcpp::executors::MultiThreadedExecutor executor(rclcpp::ExecutorOptions(), 4);
  executor.add_node(ex);
  std::thread spinner([&executor]() { executor.spin(); });

  BehaviorTreeFactory factory;
  factory.registerBuilder<Capture>("Capture", [&](const std::string & n, const NodeConfig & c) { return std::make_unique<Capture>(n, c, *ex); });
  factory.registerBuilder<Detect>("Detect", [&](const std::string & n, const NodeConfig & c) { return std::make_unique<Detect>(n, c, *ex); });
  factory.registerBuilder<PalletEmpty>("PalletEmpty", [&](const std::string & n, const NodeConfig & c) { return std::make_unique<PalletEmpty>(n, c, *ex); });
  factory.registerBuilder<PickPlaceLeaf>("PickPlace", [&](const std::string & n, const NodeConfig & c) { return std::make_unique<PickPlaceLeaf>(n, c, *ex); });
  auto tree = factory.createTreeFromText(TREE);
  printTreeRecursively(tree.rootNode());

  int moved = 0;
  while (rclcpp::ok()) {                                 // tick until the pallet is empty
    const NodeStatus status = tree.tickWhileRunning();
    if (status == NodeStatus::SUCCESS) { if (ex->dets.detections.empty()) break; ++moved; }
    else { RCLCPP_ERROR(ex->get_logger(), "tree failed: a person needs to look"); break; }
  }
  RCLCPP_INFO(ex->get_logger(), "done after %d boxes", moved);
  rclcpp::shutdown();
  spinner.join();
}
```

`printTreeRecursively` is the terminal view; Groot2 draws and monitors trees built with BehaviorTree.CPP, and MoveIt Pro and Nav2 are built on the same library.

When a tree beats a state machine: the moment you have more than ten failure cases, or when non-programmers need to read the recovery logic. When it does not: a loop with three states, which is why Ch 13 started with one.
