# Ch 6 — MoveIt 2 configuration with the Setup Assistant (week 4)

Goal: a `cell_moveit_config` package so `move_group` can plan collision-free motions for the `arm` group from `base_link` to `tcp`, execute them on the Ch 5 controller, and show it all in RViz.

## What MoveIt adds on top of ros2_control

| Piece | File in the config package | Role |
| --- | --- | --- |
| SRDF | `config/cell.srdf` | planning groups, named poses, end effector, disabled collision pairs |
| Kinematics | `config/kinematics.yaml` | IK solver per group (KDL by default) |
| Joint limits | `config/joint_limits.yaml` | velocity/acceleration limits used for time parameterization |
| Planning pipelines | `config/ompl_planning.yaml`, `pilz_cartesian_limits.yaml` | OMPL (sampling: RRTConnect…), Pilz (industrial PTP/LIN/CIRC) |
| Controllers | `config/moveit_controllers.yaml` | which ros2_control controller executes which joints |
| ros2_control | `config/ros2_controllers.yaml` | same content as Ch 5, regenerated by the assistant |
| Launch | `launch/demo.launch.py`, `move_group.launch.py` | everything, or only `move_group` |

`move_group` keeps a **planning scene**: the robot state from `/joint_states` plus collision objects you add (boxes, Ch 11). Planners sample in joint space and reject states that collide with the scene.

## Run the assistant

```bash
ros2 launch moveit_setup_assistant setup_assistant.launch.py
```

| Screen | What to do |
| --- | --- |
| Start | Create New MoveIt Configuration Package → load `~/pal_ws/src/cell_description/urdf/cell_control.urdf.xacro` |
| Self-Collisions | Sampling density to max → Generate Collision Matrix (pairs that never or always collide are skipped at planning time) |
| Virtual Joints | none: the URDF root is already `world` |
| Planning Groups | Add Group `arm`: kinematic solver `kdl_kinematics_plugin/KDLKinematicsPlugin`, Add Kin. Chain `base_link` → `tcp`. Add Group `gripper`: Add Links `gripper_body`, `suction_pad`, `tcp` |
| Robot Poses | `home` = `0, -1.57, 1.57, -1.57, -1.57, 0` for `arm` |
| End Effectors | `suction`: group `gripper`, parent link `tcp`, parent group `arm` |
| Passive Joints | none |
| ros2_control URDF Modifications | **skip**: `cell_control.urdf.xacro` already has the tag; adding it again creates a duplicate `ros2_control` block |
| ROS 2 Controllers | Auto Add JointTrajectoryController for each group → the arm one is already named `arm_controller`, delete the gripper one if the assistant created it |
| MoveIt Controllers | Auto Add FollowJointTrajectory for each group → keep only `arm_controller` |
| Perception | skip (we process the point cloud ourselves) |
| Launch Files | defaults |
| Configuration Files | path `~/pal_ws/src/cell_moveit_config` → Generate Package |

## Three edits after generation

1. `config/joint_limits.yaml`: set `has_acceleration_limits: true` and `max_acceleration: 2.0` for all six joints. Time parameterization and Pilz need accelerations; the assistant leaves them off.
2. `config/cell.urdf.xacro`: confirm it includes your `cell_control.urdf.xacro` and **not** a generated `cell.ros2_control.xacro`. One `ros2_control` block only.
3. `config/moveit_controllers.yaml`: should read

```yaml
moveit_controller_manager: moveit_simple_controller_manager/MoveItSimpleControllerManager
moveit_simple_controller_manager:
  controller_names: [arm_controller]
  arm_controller:
    type: FollowJointTrajectory
    action_ns: follow_joint_trajectory
    default: true
    joints: [shoulder_pan_joint, shoulder_lift_joint, elbow_joint, wrist_1_joint, wrist_2_joint, wrist_3_joint]
```

## Run

```bash
colcon build --symlink-install && source install/setup.bash
ros2 launch cell_moveit_config demo.launch.py
```

`demo.launch.py` starts robot_state_publisher, `ros2_control_node` with the mock plugin, the two spawners, `move_group` and RViz with the MotionPlanning panel. In RViz: drag the interactive marker at the TCP to a spot above the pallet → **Plan** → **Execute**. Then put the goal inside the pedestal and plan again: no solution, because the goal state collides.

Switch planners in the panel: Context → Planning Library `pilz_industrial_motion_planner`, Planner ID `LIN`, and plan a straight-line move. `PTP` is a joint-space move (fast, curved TCP path); `LIN` is a Cartesian straight line (needed for approach and retreat).

## What you should notice

- OMPL paths differ every run (sampling); Pilz paths are deterministic. Industrial cells use Pilz-style moves for the last 15 cm.
- Velocity scaling (panel: 0.1 → 1.0) changes execution time, not the path.
- `ros2 topic echo /monitored_planning_scene --once` shows the scene; `ros2 service list | grep move_group` shows the services your code will call in Ch 7.

Real cell: a vendor planner (such as the one in a Mujin controller) performs the same three functions, collision checking, path search and time parameterization, with its own planners tuned for cycle time. Learning MoveIt teaches you the vocabulary: scene, group, IK seed, approach/retreat, waypoints.

## Checkpoint

- [ ] `demo.launch.py` shows the cell and the MotionPlanning panel plans to a pose above the pallet
- [ ] A goal inside the pedestal or conveyor fails to plan; a goal 2 m away fails IK
- [ ] Pilz `LIN` executes a visibly straight TCP line; OMPL does not
- [ ] Named pose `home` appears in the panel's Goal State dropdown and the robot returns to it
